# Novel OS 基础数据分类体系规划方案

> ⚠️ **本方案已冻结（2026-10-10）**
>
> **冻结原因**：本方案的落点是 `categories` + `knowledge_base` 两套旧表，而 [category-unification.md](./category-unification.md)（roadmap D-10）计划删除这两者；当前活跃表为 `ref_categories` + `universal_knowledge`（9 个 Python 文件在用）。照本方案实施会把 450+ 条数据落在即将被废弃的表上。
>
> **解锁条件**：roadmap 阶段 1 完成（D-02 `context.py` 解耦 `knowledge_base` + D-10 删除旧表）后解冻。
>
> **解冻后只需做「换映射目标」级别的改造，无需重写**：
> - §4.1 字段映射表：`knowledge_base` → `universal_knowledge`，`category_slug` → `ref_categories.slug`
> - §3 四层分类树：挂到现有 `ref_categories` 二级分类下，而非新建 `categories`
> - §5 前端设计、§8 CSV 兼容性、§9 风险**均无需改动**
>
> 详见 [roadmap.md](./roadmap.md) §3.3。

## 一、方案背景

当前 Novel OS 的基础数据系统存在以下问题：
1. **缺乏编辑功能**：用户无法在 Web 控制台直接编辑/新增基础数据
2. **分类太粗糙**：只有5个分类，无法覆盖 `webnovel-writer-opencode` 的全部9个CSV数据表
3. **数据未对齐**：CSV格式（通用列+表专属列）与现有 `knowledge_base` 表结构存在差异

本方案基于对 `webnovel-writer-opencode` 项目的深入分析，设计一套完整的4层分类体系，将所有公共数据纳入统一管理。

### 2.2 通用列说明

所有CSV表共享以下10个通用列：
1. **编号**：唯一ID，带表前缀（如 NR-001）
2. **适用技能**：多值字段，用 `|` 分隔（write\|init\|plan）
3. **分类**：主题分类（角色、战斗、情感等）
4. **层级**：提醒 / 缺陷补偿 / 知识补充
5. **关键词**：高权重触发词，多值字段，用 `|` 分隔
6. **意图与同义词**：用户自然语言问法，多值字段，用 `|` 分隔
7. **适用题材**：全部或多值题材名，用 `|` 分隔（15个canonical值）
8. **大模型指令**：检索命中后直接拼给模型的执行指令
9. **核心摘要**：高权重召回与结果展示用的简明摘要（≤200字）
10. **详细展开**：补充说明，低权重召回

### 2.3 canonical_genre 题材枚举（15个）

```
都市  玄幻  仙侠  奇幻  科幻
历史  悬疑  游戏  古言  现言
幻言  年代  种田  快穿  衍生
```

## 四、数据迁移思路

### 4.1 CSV数据到knowledge_base表的字段映射

| CSV通用列 | knowledge_base字段 | 说明 |
|----------|-------------------|------|
| 编号 | code | 唯一标识，如 NR-001 |
| 适用技能 | applicable_skills | JSON数组，如 ["write", "init"] |
| 分类 | category_slug | 三级分类slug |
| 层级 | level | knowledge/compensation/reminder |
| 关键词 | - | 存入metadata |
| 意图与同义词 | - | 存入metadata |
| 适用题材 | applicable_genres | JSON数组，如 ["玄幻", "仙侠"] |
| 大模型指令 | summary | 高权重摘要 |
| 核心摘要 | content | 主要内容 |
| 详细展开 | detail | 补充说明 |
| 表专属列 | metadata | 以JSON格式存储 |

### 4.2 迁移步骤

1. **创建分类**：按4层分类体系批量创建categories记录
2. **导入数据**：编写脚本读取9个CSV文件，按映射规则写入knowledge_base表
3. **验证数据**：检查每条记录的分类关联、metadata完整性
4. **前端适配**：更新前端页面支持新的分类体系

### 4.3 字段转换规则

- **适用技能**：将 `|` 分隔字符串转为JSON数组
- **适用题材**：将 `|` 分隔字符串转为JSON数组（需做canonical归一化）
- **表专属列**：统一存入metadata字段，保留原始字段名

## 五、前端编辑功能改进计划

### 5.1 当前问题

- 缺少完整的编辑页面
- 分类选择仅支持一级分类
- 无法编辑metadata字段
- 缺少批量导入功能

### 5.2 改进方案

#### 5.2.1 编辑页面功能

| 功能模块 | 说明 |
|---------|------|
| 基础信息 | 编号、标题、分类（三级联动）、层级 |
| 内容编辑 | 核心摘要（富文本）、详细展开（富文本） |

- 采用三级联动下拉框：大类 → 二级分类 → 三级分类
- 支持搜索过滤
- 支持新增分类（管理员权限）

#### 5.2.3 批量导入

- 支持上传CSV文件
- 自动解析并映射字段
- 显示导入预览和冲突提示
- 支持跳过/覆盖冲突记录

## 九、风险与注意事项

1. **数据量较大**：约450+条CSV记录，需确保导入脚本稳定性
2. **字段映射复杂**：表专属列需统一存入metadata，需设计清晰的映射规则
3. **前端性能**：三级分类联动需优化加载速度
4. **权限管理**：新增分类功能仅限管理员使用
5. **兼容性**：需保留旧分类数据，支持平滑迁移
